## Scope delivered

- Added append-only `order_export_events` storage for successful exports and permissioned unexport actions.
- Derived the visible export state from the local export marker: `never-exported`, `exported`, or `changed-after-export` when a remote/local snapshot becomes stale.
- Added account-scoped, idempotent event recording tied to a completed export batch and its immutable selection snapshot.
- Added local re-export and admin-only unexport workflows that preserve every historical batch/event and never call a connector mutation method.
- Added authenticated API routes for export profiles, versions, batches, batch order marking, export history, and unexport with shared Zod validation, CSRF, origin, role, and account checks.

## Security, tenancy, money/time and idempotency review

- Event, batch, selection, and order access is scoped by authenticated account membership; clients cannot supply an account authority.
- Export marking requires an account member with mutation capability, requires the batch to be completed, and rejects order IDs outside the batch selection snapshot.
- Unexport is restricted to persisted owner/admin membership and requires an audited reason; operators and viewers cannot perform it.
- All state changes are local SQLite operations. No remote order/status/stock/customer/product mutation capability was introduced.
- Event recording is idempotent per account/order/batch and repeated completion is safe; conflicting batch state is rejected.
- UTC timestamps and existing integer minor-unit money rules are preserved; no floating-point financial calculation was added.
