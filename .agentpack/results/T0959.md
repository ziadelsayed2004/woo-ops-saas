# T0959 Result

## Outcome

Completed implementation and local validation. Production sync recovery is not claimed verified.

## Scope delivered

- Reproduced four failing regression cases before the fix: empty resumed collections with zero
  page count, full responses without usable counts, invalid start pages, and new runs inheriting
  a failed run's page checkpoint.
- Valid numeric counts may shrink; empty order pages now finish normally. A missing/stale count
  with a full order page probes the next page rather than discarding remaining orders.
- Malformed counts, oversized pages, invalid start pages, exhausted page bounds and repeated
  nonempty responses still fail with bounded safe codes.
- New sync runs read the latest successful cursor through the existing account/connection/status
  index. Existing jobs retain their own retry checkpoint. No successful history starts at page 1.
- Cursor parse failures now pass through sync failure/audit handling rather than leaving the run
  marked running. A run ID cannot be reused against a different connection.
- Automatic order polling remains at the existing 60-second default; no extra full sync loop,
  remote write, credential change, reset, mass replay or production cleanup was performed.
