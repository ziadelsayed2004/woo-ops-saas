## Database indexes, migrations, environment or deployment changes

- No new migration. T0807 uses the existing v5 durable `jobs` columns and claimable index from the approved SQLite schema.
- API runner configuration is bounded through `WOO_OPS_JOB_CONCURRENCY`, `WOO_OPS_JOB_LEASE_SECONDS`, and `WOO_OPS_JOB_POLL_MS`; the existing single-process start/health model remains Hostinger-compatible.

## Security, tenancy, money/time and idempotency review

- Worker contexts derive `accountId` from the claimed durable job; API contexts derive it from the authenticated session. Operations responses omit payloads and credentials.
- Repository reads/writes use account predicates; viewer reads and owner/admin/operator writes are enforced with CSRF for mutating HTTP actions.
- Woo handlers only validate and normalize remote snapshots. No connector or job API exposes a remote mutation method.
- Retry/dead-letter errors are bounded and redacted; job payloads are bounded JSON. Claiming, lease recovery, cancellation, and replay are idempotency/state guarded.
- Existing integer-minor-unit money and UTC timestamp rules are preserved.

## Known limitations and follow-up tasks

- Real sync, export, document, and backup side effects are intentionally injected adapters. Until T0808/T0809/T0810/T0813 provide those adapters, a queued job fails with a bounded `*_HANDLER_NOT_CONFIGURED` error and is observable/replayable rather than falsely succeeding.
- The in-process runner is the production default; Hostinger cron/CLI resumption remains the deployment follow-up in T0813.
