- Export file paths are metadata-only and constrained to private relative paths; physical file storage/download endpoints remain in the document/export-history follow-up tasks.

## Security, tenancy, money/time and idempotency review

- Every repository method requires authenticated account membership and queries account-scoped IDs; a selection cannot be used from another account.
- Profile and batch mutations require a non-viewer actor. Worker state transitions still require account membership and do not trust client account identifiers.
- Export field paths reject prototype-pollution segments and unsafe characters; filenames and stored paths reject traversal patterns.
- Spreadsheet values are sanitized at the output boundary. Integer minor-unit money and identifiers are not converted to floating point.
- Batch creation uses account-scoped idempotency keys; repeated completion with the same checksum/counts is safe, while conflicting state is rejected.
- Selection deletion is blocked while a batch references its immutable snapshot.

## UI/PDF/XLSX evidence

- XLSX semantic golden assertions are in `packages/exports/tests/engine.test.js`; the generated workbook is reloaded with ExcelJS to inspect rows, text number formats, frozen header, and formula-cell type.
- PDF/UI work is intentionally outside T0501 and remains covered by T0601/T0602.
