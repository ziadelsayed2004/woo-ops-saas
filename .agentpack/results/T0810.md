## Database indexes, migrations, environment or deployment changes

- Added schema migration 18: export job linkage, selection/order snapshot hashes, resumable cursor
  state, attempt count, `export_batch_snapshots`, composite account-scoped foreign keys and
  indexes.
- Export files use `WOO_OPS_DATA_DIR/private-exports` (derived from the existing configurable data
  directory), with restrictive directory/file permissions and checksum-bound reads.
- Existing backup file collection includes the private export directory; no Docker, Redis, worker
  service, or production Woo credential is required.

## Security, tenancy, money/time and idempotency review

- Worker account context is derived from the claimed job; no client account ID is trusted.
- Profile paths/config are allowlisted and bounded; formula-like spreadsheet values are prefixed.
- Private export paths reject traversal and symlink chains; writes are write-once and downloads
  verify the stored checksum.
- Snapshot and batch repositories use account-first predicates and composite foreign keys.
- Batch creation is idempotent by account/idempotency key; retry creates a new attempt and cancels a
  queued/running superseded job.
- Exported state is local only and cannot issue remote connector writes. Existing integer minor-unit
  money and UTC persistence rules are preserved.

## Known limitations and follow-up tasks

- The in-process export worker deliberately bounds one artifact to 100,000 orders and 200,000 rows;
  larger operational workflows must be split into batches. The snapshot table and worker pages
  prevent unbounded request-sized allocation and leave room for a future streaming/object-storage
  adapter.
- Carrier-specific column templates and richer visual export configuration remain follow-up UI
  work; the backend row mode and validation contract are in place.
