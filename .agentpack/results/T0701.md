## Database indexes, migrations, environment or deployment changes

- Migration 14 creates `cost_rules`, `order_cost_snapshots`, and `daily_order_facts`.
- Rules are indexed by account/scope/key/currency/effective date. Snapshots are unique by
  account/order/line and facts are keyed by account/date/currency/source/dimension hash.
- No new environment variables or remote services are required. SQLite WAL, foreign keys, and the
  existing single-process deployment remain in use.

## Security, tenancy, money/time and idempotency review

- Every analytics read/write uses `AccountContext` membership validation and account predicates;
  client-provided account IDs are not accepted.
- Cost-rule mutations require authenticated operation writes; only owner/admin can revise active
  rule windows. API writes use existing origin and CSRF checks.
- All money is validated/stored as bounded decimal minor-unit strings and calculated with `BigInt`;
  no floating-point arithmetic or cross-currency arithmetic exists.
- Dates are normalized to UTC instants and grouped in the account timezone. Invalid timezones,
  dates, currencies, ranges, rule overlaps, and amounts are rejected.
- Snapshots are inserted with `OR IGNORE`, retain source hash/rule/effective timestamp, and are not
  overwritten by later cost-rule changes. Daily facts can be safely deleted/rebuilt for a bounded
  scope.
- No connector or WooCommerce mutation capability was added.
