## Files and contracts changed

- `GET /api/v1/customers` accepts optional `productId`; the value identifies a Woo product in immutable synchronized order snapshots.
- Web customer directory, full order drawer handoff, document-files dialog, Arabic/English copy, CSS, tests, and README.

## Database indexes, migrations, environment or deployment changes

- None. The filter uses existing `orders.product_ids_json` projection and account-scoped orders.

## Security, tenancy, money/time and idempotency review

- The API derives account context from the authenticated session; product matching is account-scoped in both outer and inner SQL queries.
- Product ID is length-validated and bound as a SQL parameter. Order details use the existing authenticated account-scoped endpoint.
- Lifetime monetary totals remain integer minor units in persistence and are not narrowed by the product filter.
- No remote mutation or new background job is introduced.

## UI/PDF/XLSX evidence

- Desktop customer and document-files dialogs were captured and visually inspected after transition completion.
- E2E tests assert 12px document/customer dialog radius, action spacing, and mobile widths; Arabic drawer anchors to the left.
