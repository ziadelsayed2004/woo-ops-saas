## Database indexes, migrations, environment or deployment changes

- Migration 19: `durable-document-batches-and-private-artifacts`.
- Added account/status/update, batch/status/position, batch/order, and account/checksum indexes.
- Private files are stored under `${WOO_OPS_DATA_DIR}/private-documents`, outside the public web
  root. `WOO_OPS_DOCUMENT_FONT_PATH` should point to an Arabic-capable, licensed font in
  production deployments that generate Arabic documents.

## Security, tenancy, money/time and idempotency review

- All reads and worker transitions derive `accountId` from authenticated context/job ownership;
  no client account ID is trusted.
- No WooCommerce mutation method or request was added. Document generation consumes local
  canonical snapshots only; policy, workflow, and exported state remain local.
- Templates remain allowlisted token-only; generated files have safe account/batch paths, bounded
  sizes, private headers, atomic creation, and checksum verification.
- Batch and artifact writes are idempotent by account-scoped keys/IDs; retries preserve old
  artifacts and use a new job attempt. Stale/running items are re-queued after lease recovery.
- Document monetary values remain in the existing integer minor-unit order snapshots; no floating
  point arithmetic was introduced. Timestamps are persisted as UTC ISO strings.

## UI/PDF/XLSX evidence

- PDF engine output is produced server-side with no browser print headers. A4/A5/80mm/100x150mm
  page dimensions, QR/barcode assets, RTL/LTR content, and deterministic merged PDFs passed tests.
- ZIP bundles contain deterministic `manifest.json` plus successful order PDFs; partial batches
  keep successful per-order artifacts downloadable.
- The web workspace displays batch status/progress and private artifact download links, with
  Arabic/English copy inherited from the existing RTL/LTR shell. XLSX was unaffected and its
  golden suite passed as part of the declared command.

## Known limitations and follow-up tasks

- The identity policy records an external approval reference but does not claim legal/tax
  compliance. Before production legal invoices are enabled, obtain written approval from the
  merchant's applicable tax/legal authority or qualified tax counsel for jurisdiction, numbering,
  mandatory fields, tax registration, retention, and electronic/thermal invoice acceptance.
- A production deployment must configure `WOO_OPS_DOCUMENT_FONT_PATH` with an Arabic-capable
  licensed font; missing font configuration intentionally produces a bounded per-order failure
  for RTL documents instead of emitting unreadable output.
