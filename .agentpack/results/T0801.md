## Security, tenancy, money/time and idempotency review

- Backup IDs and manifest paths are allowlisted and resolved inside their expected roots; symlinks and unsupported file types are rejected.
- Manifest/database/file checksums are verified before any restore replacement; SQLite integrity, foreign keys, and supported schema version are checked.
- Restore defaults to dry-run; replacement requires explicit `--apply` and should run with the Node process stopped.
- POSIX backup directories/files are restricted to `0700`/`0600` where supported. Logs emit IDs/counts only, never payloads or credentials.
- The snapshot preserves all account-owned SQLite data, including local workflow, manual-order sequences, document metadata, and export history; no remote connector mutation is introduced.
