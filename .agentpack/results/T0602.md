## Database indexes, migrations, environment or deployment changes

- Migration 13 creates `document_templates`, immutable `document_template_revisions`, and
  `document_files` with account/order/template foreign keys, uniqueness constraints, byte-size
  and MIME checks, and account/order/revision indexes.
- `WOO_OPS_DATA_DIR` controls the private storage root; PDFs are written under
  `<data-dir>/private-documents` and never exposed as public static files.
- Optional `WOO_OPS_DOCUMENT_FONT_PATH` supplies an Arabic-capable font for production RTL PDF
  generation. The existing in-memory document engine remains usable for non-RTL requests.

## Security, tenancy, money/time and idempotency review

- Every template/file read and write requires the authenticated account context; no client-provided
  organization/account identifier is accepted.
- Template bodies are bounded and token allowlisted. No HTML execution, arbitrary URL loading,
  remote script, or CSS import is permitted.
- Private file paths are account-scoped, traversal-checked, size-bounded, mode-restricted, and
  checksum-verified before download. Downloads use `private, no-store`, CSP, and `nosniff` headers.
- Document generation uses canonical order payloads and the existing scoped bulk-job/idempotency
  model; no WooCommerce mutation method or remote write was added.
- This task does not calculate money; rendered totals remain canonical order values and no floating
  point arithmetic was introduced.
