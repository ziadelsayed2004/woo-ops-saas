## Database indexes, migrations, environment or deployment changes

- Added versioned SQLite migration 17 with canonical order columns, bounded projection arrays, search text, timeline events and account-first indexes for remote dates, channel/POS, payment, shipping, amounts, quantity, refund/exception, contact and search.
- No Redis, worker process, Docker or remote Woo write dependency was added. `includeFacets` is a bounded query option; table refreshes use `false` while facet consumers can use the default enabled behavior.
- Performance artifacts are generated outside the application database and remain private build evidence.

## Security, tenancy, money/time and idempotency review

- Every new order read/write/timeline query carries authenticated `accountId`; API never accepts a client-owned account identifier. Membership and operator-write checks are applied to mutations.
- Remote payloads remain in private storage columns and are never returned by order query/detail APIs. Recursive output redaction removes source payload fields, transaction identifiers and sensitive/private metadata entries.
- Woo connector requests remain GET-only with the existing HTTPS, DNS/private-network, redirect and origin protections. Resync queues a local `sync.incremental` job and never calls a Woo mutation endpoint.
- Monetary values remain integer minor-unit strings and all persisted timestamps remain UTC/source-aware. Refund state and canonical amount projections are deterministic and bounded.
- Timeline event keys, optimistic version predicates, selection watermarks, saved-view validation and durable resync idempotency preserve retry/replay behavior.

## UI/PDF/XLSX evidence

- The order workspace visual baseline and accessibility artifacts passed. Existing XLSX/PDF consumers passed in the unit/E2E workspace gates; this task supplies their expanded canonical order input without changing the private-file boundary.

## Known limitations and follow-up tasks

- No live Woo credentials were used; deterministic fixtures and fake HTTP servers cover local connector/sync paths. Live-store authorization remains an external deployment verification step.
- Facet counts are intentionally opt-in for high-frequency table refreshes; the API default still returns bounded facets for consumers that need them. A later performance task may materialize facet tables if very high-cardinality installations require it.
