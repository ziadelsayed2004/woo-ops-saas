## Security, tenancy, money/time and idempotency review

- All operation repository queries include account scope; mutation actors must be account members and viewers cannot write.
- HTTP writes require authenticated owner/admin/operator role plus the existing CSRF token. Client account IDs are never accepted.
- Selection/job payloads are JSON-validated and size-bounded; SQL fields/operators remain allowlisted and no raw SQL is accepted from clients.
- Watermarks and persisted timestamps are normalized to UTC ISO strings. Monetary values remain existing integer-minor-unit strings and are not recalculated here.
- Bulk creation is idempotent by `(account_id, action, idempotency_key)` and conflicts if the same key changes selection/parameters.
- The action allowlist contains no remote mutation operation; `resync` is explicitly documented and previewed as read-only.
- Creation, update, retry, cancel, and deletion operations emit concise account-scoped audit events.
