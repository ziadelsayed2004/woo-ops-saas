# T0818 Task Result

## Outcome

Migrated the complete persistence runtime from the native `better-sqlite3` addon to Node 22.18's
built-in `node:sqlite`. A typed compatibility layer preserves the existing synchronous repository
contract, normalizes row prototypes and change counts, supports nested transactions with savepoints,
retains PRAGMA behavior, and uses Node's online SQLite backup API. Existing SQLite files and schema
version 20 remain compatible.

Removed `better-sqlite3`, its type package, prebuild-install and application node-gyp requirements
from both workspaces and the lockfile. Restored Node 22, Vite 7 and Node-22 CI. Hostinger now uses
`npm ci --include=dev && npm run build`, which supplies TypeScript/Vite even when the platform's
initial dependency install omits development dependencies.

## Deployment contract

- Node version: `22.x` (minimum 22.18).
- Repository root: `./`.
- Build command: `npm ci --include=dev && npm run build`.
- Output directory: `.`.
- Entry file: `apps/api/dist/index.js`.
- `PORT` is supplied by Hostinger and must not be configured manually.
- Data directory and database remain private writable paths outside `public_html`.

## Invariant review

No Woo mutation API was added or changed. Remote records remain inbound-only; export/workflow state
and manual orders remain local. Existing account isolation, CSRF/session, job idempotency, immutable
export/document snapshots, backup checksums and path protections passed unchanged tests. Node 22
labels `node:sqlite` experimental, but it is unflagged since Node 22.13 and the exact deployed minimum
is pinned and covered by the release gates.
