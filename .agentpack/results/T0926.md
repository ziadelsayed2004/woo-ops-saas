## Security, tenancy, money/time and idempotency review

- Account identity comes only from the authenticated session; the request cannot select an account ID.
- Both HTTP and repository layers require the owner role, and destructive SQL is explicitly scoped by `account_id`.
- Running jobs block reset; queued jobs are removed transactionally. Repeating a completed reset is safe and produces a fresh audit event.
- File cleanup validates the account identifier and resolved path, refuses symlinks/non-directories and is tested against sibling-account deletion.
- WooCommerce connector records and credentials are preserved and no remote write is performed.

## Known limitations and follow-up tasks
