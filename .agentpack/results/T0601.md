## Database indexes, migrations, environment or deployment changes

- None. This task is a pure document-generation package change. Generated bytes remain the caller's responsibility to store outside the primary database.

## Security, tenancy, money/time and idempotency review

- Templates and order payloads are normalized at the package boundary with bounded text, line, and batch sizes; arbitrary objects are never evaluated as code or template expressions.
- No connector, HTTP, credential, or remote mutation path was added.
- Document source identity is captured in a hash and template version; PDF bytes receive a checksum for storage/idempotency keys.
- Monetary values are rendered as supplied text from canonical order snapshots; this package does not perform floating-point calculations.
- RTL output requires caller-provided font bytes, preventing silent substitution of a font that cannot represent Arabic glyphs.

## UI/PDF/XLSX evidence

- PDF evidence is generated in memory by the test suite and parsed with `pdf-lib`.
- A4 is validated at 210x297mm, A5 at 148x210mm, thermal at 80x150mm default, and label at 100x150mm within PDF point precision.
- Arabic-capable Windows Arial is used when available by the deterministic local test fixture; the test skips only when no system font is available.

## Known limitations and follow-up tasks

- Persistence/API document template records, file storage, batch jobs, ZIP downloads, print-preview UI, and visual golden image baselines remain in downstream document tasks. This task deliberately supplies the reusable generation engine only.
- The default thermal height is 150mm and can be configured per request between 50mm and 500mm.
- Browser-based pixel snapshots are not claimed here; the current repository's broader Orders visual baseline mismatch remains a separate follow-up.
